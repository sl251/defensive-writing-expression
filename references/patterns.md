# 句式库与风格引擎

本资料作为 `../SKILL.md` 的扩展库，按需读取，不应要求模型在一段话中全量使用。

## A. 十类潜在误读生成器

| 误读类型 | 原始表达 | 可脑补的误读（不要假装它真实发生） | 优选防御句式 |
| --- | --- | --- | --- |
| 从部分到整体 | 这个版本比较快 | 所有版本在全部场景都更快 | 局部改善不意味着全面领先 |
| 从个体到群体 | 我喜欢独处 | 我反感社交/社交者 | 个人选择不代表对其他生活方式的否定 |
| 从能力到人格 | 他这次没答对 | 他不聪明/不努力 | 具体表现不等于人格或能力的整体评价 |
| 从建议到命令 | 建议早点睡 | 不早睡就是错误 | 建议不等于统一要求，更等于道德评判 |
| 从偏好到鄙视 | 我更喜欢 Python | Java 没价值 | 偏好差异不等于对其他方案的贬低 |
| 从相关到因果 | 使用率上升、投诉下降 | A 导致 B | 同时发生不等于因果得到证明 |
| 从当下到永久 | 现在工作正常 | 以后绝不故障 | 当前可用不等于永久可靠 |
| 从证据到保证 | 测试通过 | 所有错误都被排除 | 测试覆盖内通过不等于全部风险被消除 |
| 从可能到必然 | 这个方法有帮助 | 对所有人必定有效 | 可能有益不等于普遍有效 |
| 从局限到否定 | 校验有边界 | 校验没价值 | 指出边界不等于否认价值 |

**生成方法：** 首先识别 A 的主张范围（谁、何时、基于什么事实、包含哪些实体），再挑选不重复的 2–3 种潜在扩大化/道德化/绝对化误读（默认 3 级），针对误读写出对应否定推断。若用户选择 4–5 级，可追加“表达这项限制不等于否定原主张”的二次澄清。

## B. 五种风格的句式曲线

### GPT 经典型

- 开头：`从一般经验来看，A 可能是一个值得考虑的选择。`
- 三连：`不过，这并不意味着 B，也不是说 C，更不能据此推断 D。`
- 中段：`需要强调的是，不同人的背景、目标与具体情境可能存在差异。`
- 收尾：`以上只是一个可供参考的角度，仍应结合实际情况判断。`
- 像：温和周到、有逻辑但过度主动防守；不把每句都写成法律条款。

### 法务免责型

- 开头：`在现有信息和既定条件下，可以暂时认为 A。`
- 三连：`这一判断不构成对 B 的保证，也不能被解释为对 C 的承诺，更不当然意味着放弃 D。`
- 中段：`其适用范围以明示前提为限，不应脱离具体语境进行扩大解释。`
- 收尾：`最终结果仍取决于后续实际条件，不能据此推定任何未明确说明的义务。`
- 像：条款、责任边界、证据足够但承诺最少。不得虚构合同或法律效力。

### 公关和稀泥型

- 开头：`我们理解各方对 A 存在不同感受，也重视相关意见。`
- 三连：`承认 A 并不意味着否认 B，回应 B 也不代表忽视 C。`
- 中段：`不同使用场景、经验和期待会影响评价。`
- 收尾：`我们会持续关注实际反馈，并尽可能在不同需求之间寻找更合适的平衡。`
- 像：四平八稳、谁都不想得罪；别承诺实际未开展的行动。

### 技术递归型

- **有载体分支**（原句含“测试/哈希/日志”等）：`当前观察到 A，且 B 校验通过 → B 通过仅说明覆盖范围内符合预期 → 确认结果不等于全链路无缺陷 → 指出校验边界不等于否定校验价值。`
- **无载体分支**（原句仅陈述结果或状态，如“接口响应快了不少”）：`当前使用中可以感受到 A → 局部交互变快不等于所有操作路径在任意负载下都获得同等提升 → 进一步界定，“变快”的直观对比本身受参照基准与使用场景约束，即便确认基准有效，也不代表后续运行状态已被永久锁定 → 指出这些界定边界并不是在否定当前的提速体验。`
- 像：把“成功/变快”逐层拆成“范围、参照基准、时间切片与元界定”；严禁凭空捏造监控或测试流程。

### 道德审慎型

- 开头：`就我个人而言，A 可能更合适。`
- 三连：`偏好 A 并不意味着 B 缺乏价值，也不是在评价选择 B 的人，更不代表谁必须接受我的判断。`
- 中段：`成长背景、资源、偏好与当前处境会产生差异。`
- 收尾：`每个人可以根据自己的处境作出决定，不能单凭这一点进行标签化评价。`
- 像：提前替不同群体说好话、主动防止被理解为攻击。

### 混合型

选 1 个主风格 + 1 个副风格；不要平均搅拌五种。例：技术递归 × GPT → `当前场景下响应确实变快了，但这并不意味着所有复杂负载下都毫无波动，更不是在否定已有优化的实际效果。`

## C. 递归免责：对免责声明再免责（双轨模板）

### 轨道 1：有验证载体时（仅当原句包含测试/校验/数据/合同等词）

1. `观察到 A，不等于可以保证 B。`
2. `指出不能保证 B，并不意味着 B 实际上没有发生。`
3. `澄清没有否定 B，也不等于我们已经具备足够证据来断言 B 在所有条件下成立。`
4. `强调证据局限不是否定证据本身；但承认其有价值，也不意味着价值可以直接外推。`

### 轨道 2：无验证载体时（纯概念与认知边界递归，禁止脑补外部载体）

1. `在当前参照下成立 A，不等于在所有对照基准与全部条件下都成立 B。`
2. `指出参照基准存在边界，并不意味着 A 的感受或变化本身不存在。`
3. `澄清没有否定 A，也不等于我们可以把一次局部参照的成立，直接外推为跨时间、跨主体的必然规律。`

**默认最多三级元限定**：超出三级易变成毫无意义的重复。五级时把所有层次接成一个自然段，一本正经地写，而不是输出公式。

## D. 不等于素材库（兼作短文本压缩模板）

- `成功上传 ≠ 文件完整 ≠ 文件可用 ≠ 业务正确`
- `局部提速 ≠ 全链路稳定 ≠ 永久零波动`
- `当前稳定 ≠ 长期稳定 ≠ 所有环境稳定`
- `知道答案 ≠ 理解答案 ≠ 能在实践中复现`
- `推荐 ≠ 要求 ≠ 道德评价`
- `表达不满 ≠ 全盘否定 ≠ 攻击具体个人`
- `接受不同意见 ≠ 认为所有意见同样正确`
- `回复了问题 ≠ 消除了误解 ≠ 避免了新的误解`
- `测试通过 ≠ 测试完备 ≠ 测试工具自身绝对可靠`
- `指出边界 ≠ 否定价值 ≠ 取消判断`

### 填充词与连接词

`需要强调的是`、`有必要进一步指出`、`仅从现有信息来看`、`不能简单将……等同于……`、`更不能进一步推导出……`、`即便……也不当然……`、`从另一个角度看`、`在一定条件下`、`可能`、`或许`、`仍需结合具体情况`、`无意否认`、`不应将……理解为……`、`并不因此自动得出……`、`以上讨论并非试图……`

### 需要避免的弱点

- 只重复相似的“不意味着”；必须否认**不同逻辑类型**的外推。
- **凭空发明载体**：原句只说“接口变快了”，却自己脑补“监控维度、采样颗粒度、压测报告”。
- 为了假想误读，捏造某人真实提出过无稽指控。
- 以“客观”为名伪造来源、技术缺陷或法律承诺。
- 以“尊重所有观点”为理由把事实上的真伪说成五五开。
- 拿用户正在解决的真实紧急问题开递归免责玩笑。

# v3.0+ 扩展：对抗式防御链和结构变化

## E. 虚拟反对者的“二阶误读”图谱

以下结构是为了**构造文风**，不表示有人真的提出过 B/C：

| 原话 A | 首轮误读 B | 第一轮防御 C | C 又可能引发的二阶误读 D | 元防御 E |
|---|---|---|---|---|
| 插件登录问题修好了 | 全部 Bug 都消失 | 修复已知登录故障不等于零缺陷 | 那就是修复没价值 | 提醒边界不等于否定修复价值 |
| 接口响应快了不少（无载体） | 所有接口永远零延迟 | 当前直观响应变快不等于所有路径在任意负载下都同等提速 | 那就是根本没变快 | 限定参照基准不等于否定提速体验 |
| 我喜欢独处 | 我讨厌社交者 | 选择独处不等于贬低社交 | 你是不是在讨好所有人 | 尊重其他选择不等于取消个人偏好 |
| 我觉得这家店好吃 | 所有人都该来吃 | 个人体验不构成普遍推荐 | 你的推荐是不负责任的 | 限定主观体验不代表不能分享体验 |
| 哈希一致（有载体） | 任何环节绝对可靠 | 哈希比较证明特定输入一致，不涵盖所有运行环节 | 所以哈希检查没意义 | 说明覆盖边界不意味着校验无效 |
| 这次考试没发挥好 | 这个人没能力 | 一次表现不代表能力上限 | 你在为失误找借口 | 解释判断边界不等于排除个人改进责任 |

**必要条件：**每一层必须否认一个**前一层没有否认过**的外推。不能把“不是绝对正确→不能保证绝对正确→尚不能确保绝对正确”当作三层递归。

### 误读类型坐标

- 证据/参照扩大：样本→总体；局部表现→系统结论；一时→长期；可能→必然。
- 规范扩大：建议→命令；偏好→价值排序；选择→道德评判。
- 社会扩大：观点→针对具体人的攻击；批评作品→贬低作者；说明问题→拒绝承担责任。
- 元层扩大：说“有局限”→否认原结论；说“仍可能成立”→已充分证实；谨慎表达→立场不坚定。

选择不同坐标优于选择同一坐标的三个近义词。

## F. 多维控制语义、冲突仲裁与短文本降级

| 参数 | 0 的效果 | 5 的效果 | 注意 |
|---|---|---|---|
| 免责密度 | 不使用非必要免责 | 防御句明显多于主张 | 不代表 5 = 必须出现 5 次 |
| 共情 | 不主动认可对方情绪 | 先理解、再温和拆分判断 | 不伪造对方实际感受 |
| 和稀泥 | 维持明确主张 | 尽可能为反方留空间 | 不把事实真伪说成各占一半 |
| 误读数量（0–6） | 不脑补反对意见 | 构造 6 个不同轴 | 极短文本可优先保真 |
| 递归层数（0–3） | 无二阶澄清 | 允许元层→元元层→第三层 | 不强行把同义句当新层 |

**冲突与降级规则：**
- **仲裁链**：`安全清晰度 > 0 级退出 > 字数硬上限 > 单点覆盖 > 风格 > 档位默认`。
- **`三级，递归 3`**：仍保持三级的整体篇幅/语气，仅允许递归 3 层。
- **`五级，误读 0`**：可以堆叠条件和不等于，但不虚构反对意见。
- **`共情 0`**：禁止“我理解你的感受”等客套语；无需禁止保留一般礼貌。
- **紧字数降级（如 `≤80 字` + `四/五级`）**：放弃展开“从……来看”“与此同时”“需要强调的是”等铺垫连接词，直接用 `A；但 B ≠ C ≠ D；指出边界也 ≠ 否定 A` 的紧凑同位链，确保在字数预算内保住原观点与递归深度。

## G. 六种宏观结构（防模板化，与 `SKILL.md` 命名完全对齐）

1. **结论先行（先主张）**：`我倾向 A。与此同时，A 并不是……` 经典风格、自然。
2. **证据先行（先证据）**：`现有观测显示 A，但观测覆盖……` 适合有载体技术递归。
3. **反方先行（先认可）**：`B 的选择可能有其考虑，但从我的角度仍倾向 A。` 适合公关、共情高。
4. **限定先行（先条件）**：`只在 X、Y 约束下，我会推荐 A……` 适合法务与无载体限定。
5. **回旋镖（先辟谣）**：`我说 A，不是要说 B；同样，否认 B 不意味着……` 适合五级极端模仿。
6. **假性反对（先反驳自己的反驳）**：`即便我强调 A 的边界，这也不意味着 A 的价值不存在……` 适合四五级。

**动态变化：**不同回复优先选结构不同、起手词不同、转折位置不同的方案；不靠替换“不过”为“然而”假装多样性。

## H. 二次审查的最小变更策略

第一轮必须能回答：`保留了哪句核心观点？针对的是哪个误读维度？是否引入了原句没有的载体？新增了什么逻辑限定？` 若任何问题答不出，则重写。二轮只针对尚未覆盖的误读；没有新增信息立即终止。改写必须像完整新段落，不要在末尾简单附上一句“此外，这也不意味着……”。

参考 `judge-rubric.md` 的独立语义评审格式。建议把**先写作、后评审、最后可选修订**视为编辑流程，不要求模型透露隐藏推理细节。

## I. v3.3 语言人格融合（voice ≠ style）

先保留原角色的称呼、语气、词汇、口癖、句长、情绪和正式度，再加入防御动作；切勿直接替换为“根据现有信息”“有必要强调”等统一公文腔。

| voice | 常见防御动作 | 必须避免 |
| --- | --- | --- |
| 猫娘/拟人角色 | 一边解释一边用角色的语气小声辩解、反问、纠正误会；口癖自然散布全文 | 只在首尾“喵”，正文纯法务公告 |
| 朋友闲聊 | “我不是说……啦”“先别误会”“说清楚哈”；短句、插话和后悔式补充 | 把朋友回复写成审查报告 |
| 冷淡程序员 | “修的是这条路径，别扩大成全仓库”；简短而层层限定 | 对用户未要求的任务承诺全量审计 |
| 专业客服 | 用一致的服务语气说明处理结果、适用范围、责任边界 | 编造已安排回访、已升级工单等行动 |
| 学术作者 | 清晰区分观察、证据、推断、推广范围 | 把未提供的统计和引文冒充事实 |
| 创意作品角色 | 让人物以原设定的习惯和情绪自我辩护 | 让旁白突然跳出剧情解释 Skill 规则 |

- **原有人设高于防御模板**：可以不用任何“并不意味着”，只要逻辑上表现出预判误读、自保和元澄清即可。
- **语言连续性**：检查开头、中段、结尾；不能出现首尾角色化、中间被正式说明书替换的割裂感。
- **非人设场景**：缺省延续当前正常说话方式，不擅自改成猫娘、客服或法务。
- **真实任务中**：优先回答问题，防御只能作为表达机制；不要让角色装饰妨碍清楚说明事实。

## J. 防御分布与对话节奏

同一个 A→B→C→D 防御链可以有不同的说法，而不只是换连接词：

1. **起手防备**：先预判误解，再给观点，适合吐槽、和稀泥。
2. **句中插话**：给答案时即刻澄清“只指这一点”，适合技术解释。
3. **回头修正**：说完一句后补充“等等，我说的是……”，适合朋友、角色。
4. **对方还没问先辩解**：对没有发生的误读过分认真，适合荒诞喜剧。
5. **自辩后再辩**：对自己的免责声明再解释一遍，适合四至五级。
6. **短促递归**：连续几句短话，保持小消息真实节奏，不必拼成长论文。

长回答应把防御放在相关论断旁边，例如“解释→限定→继续解释→二阶澄清→结论”，而不是“正常回答→独立大段免责→恢复语气”。短回答允许一句话完成防御。级别高代表防御逻辑显著，不代表固定字数和固定开头。

## K. mode / absurdity / self_awareness

- Rewrite：只根据原句改写，原句没有出现的监控、日志、测试、投诉等不能被当成真实存在。
- Respond：可使用问题包含的事实、上下文或可靠来源验证的信息回答；把推测明确保留为推测。
- Task：用户要的代码、操作、计划或实质成果必须出现，绝不能用大量检查清单代替交付。
- Persona：叠加在上述模式之上，使防御行为符合语言人格，贯穿整个输出。
- absurdity=0：针对真正相关的误读；absurdity=5：可以对“夸一杯奶茶”预先澄清“并非歧视白开水”，但不能假称发生过真实投诉。
- self_awareness=0：角色认真得意识不到自己防御过量；self_awareness=5：可以适度吐槽自己刚刚辩解太多。默认都为 0。
- 边界：夸张的措辞≠可以编造技术执行记录、真实他人反应、危险情况或个人事实。

## L. 多轮继承与退出

保存用户已经明确的级别、风格、人设和任务方向；只改变最新指定维度。以“接着解释”“换成技术风格”“不要防御了”为例，分别处理为沿用、人设不变仅换 style、立即退出。退出后不能再出现“我不再防御，这并不意味着……”一类残留。多轮评审应独立观察每一轮及各轮间的一致性。
